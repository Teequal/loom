# UX review and next steps (25 Oct)

Jacob's bar: a UX that offers something different or better, done in a very polished way, that people enjoy using. Controls should sit out of the way of the main show, and when they have to be visible, they should fit in rather than stand out.

## What already sets Loom apart (keep and build on)

- **One box at the table.** Type what happened and options start streaming in about 3 s. Nothing else competes for attention.
- **The loom is walkable.** Every name in any text is a link. Hover shows a preview, a click opens the inspector, and the breadcrumb trail lets you follow a thread from a character to a condition to someone else's state. No competitor does this. It's the clearest expression of the idea and the thing to lean into.
- **The session as a tree.** Develop, use a piece, develop again, then wrap up with what's already recorded. It turns a reactive tool into a planning partner without a separate "prep mode".
- **Calm visual language.** Warm paper and ink, a single brass accent for "this ties to the story", and dark mode that holds up.

## Done in this pass

- **Wrap-up asks open questions first.** Unanswered yes/no items from the table appear above the notes, can be answered one by one or with "No to all", and the session can't close until they're answered (enforced on the server too).
- **One quiet control instead of a toolbar.** Model, tone and "ask before risky changes" moved behind a single line under the box ("Quick · Restrained"), which opens a small panel. The box is now just the box and the button.
- **Controls that belong to Loom.** The browser's range sliders and checkboxes are replaced by custom controls used everywhere:
  - dots on a thread, for steps like tone and how far ahead;
  - text tabs, for a choice of a few words;
  - switches, for on/off settings.
  Develop's reach, the tray's auto-approve and the campaign settings all use them.
- **Story text in a book face.** Options, developments, ideas, descriptions and session notes are set in Newsreader; the interface stays in Geist. Narrative now reads differently from chrome: the story feels like a story, the tool feels like a tool.
- **Quiet inputs and readable labels.** The campaign picker and the session number field match the rest of the page. "recap s3 2026-10-24 12:51 #e4" now reads "Session 3 notes · 24 Oct, 12:51", and table saves read "At the table, session 3 · 01:53".

## Findings, by priority

### P1: what most affects enjoyment

1. **First run is a blank page.** A new campaign (e.g. *Temples of Fate*) opens to an empty box with nothing to suggest, and that's when a new DM decides whether Loom is for them. It needs:
   - a short welcome in three steps: name the campaign; paste your last session's notes, or start fresh; try a moment;
   - **"Try it with a sample campaign"**, using the potion story;
   - example moments as tappable chips.
2. **After you use an option, the page stays long.**
   - The unused options should fold into one line ("2 other options ▸").
   - The used card should take focus, with what it added to the loom right under it.
   - Develop inside Develop draws boxes within boxes. Nested branches should read as an indented thread (a left rule and a lighter background), not as more cards.
3. **Background work is silent.** Extraction finishes 10–15 s later with only a small status line. Two changes:
   - A quiet toast: "Added 3 to the loom: Ysolde offers a trade…", linking to the inspector.
   - A brief glow on the timeline dot.
   That rewards each choice and shows the loom growing.
4. **Mixed visual vocabulary.**
   - Unicode glyphs (✓ ✎ ↳ ★ × ⟲ ◆) sit beside an SVG icon. They should move to one small icon set drawn to match.
   - Buttons come in four styles. They should come in three: primary filled, secondary outline, tertiary text.
5. **Mobile.**
   - The sticky box and the questions tray can take nearly half a phone screen. The box should collapse to one line while you scroll, and expand on tap.
   - The inspector's bottom sheet needs a drag handle and swipe-down to close.

### P2: what makes it feel crafted

6. **Jump anywhere (⌘K).** A command palette over the loom index: type "Vex" and open her, or a thread or a session. The index already exists, so this is cheap, and it makes the loom feel instant.
7. **Keyboard at the table.** 1–3 uses an option when the box is empty; D develops the focused option. DMs running online keep their hands on the keys.
8. **A neighbourhood view in the inspector.** A small drawing of the open node with its direct ties (people, threads, places), clickable. It's the seed of the string board, appears exactly where it's useful, and is the most "Loom" visual.
9. **The prep review opens with a sentence.** "Session 6 moved 4 threads, added Lemon the squire, and Iresia reached the palace." Detail below, folded by default.
10. **Loading states.** A gentle shimmer instead of a pulse; Develop's elapsed timer is right, so keep it.

### P3: housekeeping

11. **Accessibility.**
    - A consistent visible focus ring.
    - `aria-live` on the questions tray and the toast.
    - Check contrast of muted text on the brass-tinted tray.
12. **Spacing scale.** Use a few fixed text sizes instead of the many custom pixel sizes (15.5, 14.5, 13.5…), so the page settles visually.
13. **Brand.** A small wordmark for "Loom." built on the thread motif already in the timeline: a line joining dots.

### Engine quality seen while reviewing

- **A made-up mechanic:** a fixture option asked Bram for "a madness roll" with no such rule in the campaign. The check catches rules named in the mechanic field, but not ones invented in free text. Worth a check against the campaign's rule names.

## Next steps for the project (my view)

1. **Polish sprint (1–2 weekends): P1 items 1–5, plus ⌘K.** This is the difference between "works" and "I want to open this". Do it before anyone else sees it.
2. **Durability (a weekend).**
   - Background extraction should survive a server restart: a small job table instead of in-memory work.
   - Failures should be visible with a retry.
   - Add an "export campaign" button, so users trust that their notes are theirs.
3. **Hosted test with 3–5 DMs (a weekend).**
   - One deployment (Vercel plus a hosted libSQL such as Turso) behind a simple invite password, with an API spend cap.
   - A one-tap "this was useful / not" on options and developments. "Used" is already logged, so with ratings we can measure.
   - Watch three things: how often an option gets used, time to the first option, and whether people come back between sessions.
4. **Measure and tune.** A small private dashboard:
   - use rate by model and tone;
   - Develop depth;
   - questions answered versus auto-approved;
   - cost per session.
   Rerun the blind test, including Develop.
5. **Then Phase 2, in this order:**
   - Accounts.
   - A Discord companion: the table where online DMs already are. Ask from Discord, use from Discord, with the same loom behind it.
   - Paid tiers matching Quick, Balanced and Best.
   - The full string board, grown from the inspector's neighbourhood view.
